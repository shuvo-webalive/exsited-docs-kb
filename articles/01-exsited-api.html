The Exsited API lets your own software read and change your Exsited data: accounts, orders, invoices, payments, items, purchasing, work and settings. This article explains what the API is, which tools you can use with it, and where to find the full developer documentation.

Open the developer documentation

Who this is for

The API is for developers building an integration with Exsited, for example creating accounts from a sign-up form, syncing orders and invoices with another system, or reading payments into a reporting tool. You do not need the API to use Exsited day to day; the same work can be done in the Exsited app.

Two ways to use it

Option Best for
An SDK
Python, JavaScript, PHP, Java, .NET, Dart or Go		 Most integrations. The SDK gets and renews the access token for you, sends your request body as JSON and gives you the JSON response back. The functions are the same in all seven languages.
The REST API directly
Any language, or cURL		 A language without an SDK, or a quick one-off call. You request an access token yourself and send it with each request.

Get started

1Get your API credentials. You need your API base URL, client ID, client secret and redirect URI. Your Exsited contact can provide them. Authentication explains each one.

2Install the SDK for your language. See Installation.

3Make your first call. Authentication shows how to set up a client in every language, and every endpoint page shows the call in all seven SDKs and cURL.

Keep your credentials private

The client secret gives access to your Exsited data through the API. Keep it in an environment variable or a secrets manager, never in source code or a shared document.

One running app per set of credentials

A new access token for the same credentials ends the previous one. If two apps share one set of credentials, they keep signing each other out. Give each app its own credentials.
