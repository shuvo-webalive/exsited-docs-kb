The platform APIs let your software work with your customer portal, your integrations and the data around your Exsited instance. You can log portal users in and manage their passwords, read your integration connections, create external databases and work with their records, and read overview reports over a date range. You can also manage OAuth applications, read the root organisation, manage child organisations and read webhook deliveries. All thirty-five endpoints are available in all seven Exsited SDKs.

All endpoints

Portal

These endpoints log portal users in, change, set and reset their passwords, and activate or validate portal accounts, and the Portal overview explains each one.

EndpointMethodPath
Activate a portal account
Activates a portal account with an activation code.		POST…/portal/activate
Change a portal password
Changes a portal user's password when you send the current one, and returns a message.		POST…/portal/change_password
Log in a portal user
Checks a portal user's email and password and returns the user with the portals they can open.		POST…/portal/login
Reset a portal password with a code
Sets a new portal password using a reset code.		POST…/portal/reset
Request a portal password reset link
Asks for a password reset link for a portal user's email and returns a message.		POST…/portal/reset_link
Validate a portal account with a code
Validates a portal account with a code.		POST…/portal/validate
Set a portal password by email
Sets a portal user's password from their email alone, without the current password.		POST…/portal/change

External databases

These endpoints create external databases with tables and records, then list, read, search, insert and update their records, and the External databases overview explains each one.

EndpointMethodPath
List external databases
Returns the external databases on your instance, each with its name.		GET…/external_databases
Create an external database
Creates a database with its tables and first records, and returns its name and a message.		POST…/external_databases
Retrieve an external database
Returns one external database by name, as a list under data.		GET…/external_databases/{db_name}
Insert records into an external database table
Adds rows to one table of a database and returns the inserted data.		POST…/external_databases/{db_name}/insert_records
Search an external database table
Returns the rows of one table of a database, with a count.		POST…/external_databases/{db_name}/search
Update records in an external database table
Changes column values in the rows of a table that match a condition, and returns a message.		PATCH…/external_databases/{db_name}/update_records
Retrieve the columns of an external database table
Returns the columns of one table of a database, as a list under data.		GET…/external_databases/{db_name}/tables/{table_name}

Good to know

Some changes cannot be taken back

Set a portal password by email does not ask for the current password, and the old password cannot be put back. An external database cannot be deleted through the API; to put its tables back to a known state, create it again with replace set to true. Creating a child organisation changes your organisation hierarchy and assigns an existing user to it.

Reports can be slow

A report can take up to 90 seconds. Set your client timeout above the default 30 seconds, such as 120. Amounts and counts in a report, such as amount, count and net_gain, are strings, not numbers.

  • A portal user is an account with portal access. Create the account with grant_portal_access set to true and a grant_portal_password, then log in with its email_address and that password. Every portal request body sits under portal.
  • Each external database record is a list of field and value pairs. A record looks like {"record": [{"field": "company", "value": "Acme Pty Ltd"}]}.
  • The client id and secret of a new application are never returned. Exsited generates them, and the API does not return them.
  • Organisation records sit under organization, spelled with a z. The root organisation is read only and never appears in List child organisations.
  • No endpoint lists webhook deliveries. Keep the whk_ id each delivery carries, so you can read it later.
  • External databases page differently. Their listings use has_next, has_prev and per_page; the other listings here send pagination.next_cursor as cursor while has_more is true.
