The items and fulfilment APIs let your software manage the products and services you sell and buy, and the stock and deliveries behind them. You can create and update items, set their sale, purchase and inventory sections, add stock to warehouses and read stock changes. You can also work with units of measurement, zones, shipping packages, shipping rules and fulfillment profiles and terms, record items sent to customers, read items received from suppliers, take bookings, hire out rental assets and handle customer returns. All 156 endpoints are available in all seven Exsited SDKs.

Good to know

Deleting a booking deletes any order with that id

Delete a booking removes whatever order has the id you send, of any type, so check the id first. Stock that has moved also locks records: a fulfillment cannot be deleted once any of its stock has been sent, and a completed item receipt cannot be deleted. These deletes are refused with 400 and the code stock_committed. A fulfillment created through the API comes back shipped, so it cannot be deleted. Receiving returned stock for a return merchandise authorisation commits it too, and Update an RMA and Delete an RMA currently return 500, even for a draft.

Address an item by its id code

Item paths take the item's id, such as ITEM-0001. Do not use its uuid, or the integer id that Retrieve an item's sale settings and Retrieve an item's purchase settings return.

  • Every item write sits under item. The one exception is Upload an item's image, which sends image_base64 at the top level of a JSON body.
  • An item that an order uses cannot be deleted. Delete an item returns 409 for it, and retrying does not help. Deactivate an item and Reactivate an item can return 500, so read the item afterwards and check its status. Delete a note file currently returns 404 attachment not found, even for a file the note's files listing shows.
  • Stock quantities are strings, and lists come a page at a time. In inventory adjustments, adjustment_amount and every quantity_* field arrive as text, so convert them before doing arithmetic. Listings put their records under data; send limit, then pass pagination.next_cursor as cursor until has_more is false.
  • A shipping rule's configuration cannot be set yet. A configuration names each zone by its dashed uuid: the 32 hex digits after zn_ in the zone's id, grouped 8-4-4-4-12. Set a shipping rule's configuration currently fails: the zn_ id or the 32 digits alone return 400 zone not found, and the dashed uuid returns 500. Update a zone currently returns 200 but leaves the zone unchanged, so read the zone afterwards.
  • Return merchandise authorisation writes take the rma_ id; the reads under it take the code. The note and receipt reads return 404 for an rma_ id.
  • Units of measurement cannot be created yet. Create a unit of measurement currently returns 400 validation_error without naming a field, so updating and deleting a unit have not been confirmed to work either. A shipping package's *_uom fields take a unit's bare uuid, not its prefixed id, and setting them has not been confirmed to work.
