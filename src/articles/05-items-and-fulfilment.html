The items and fulfilment APIs let your software manage the products and services you sell and buy, and the stock and deliveries behind them. You can create and update items, set their sale, purchase and inventory sections, add stock to warehouses and read stock changes. You can also set up units of measurement, zones, shipping packages, shipping rules and fulfillment profiles and terms, record items sent and received, take bookings, hire out rental assets and handle customer returns. All one hundred and fifty-six endpoints are available in all seven Exsited SDKs.

Good to know

Deleting a booking deletes any order with that id

Delete a booking removes whatever order has the id you send, of any type, so check the id first. Stock that has moved also locks records: a fulfillment cannot be deleted once any of its stock has been sent, a completed item receipt cannot be deleted, and only a draft return merchandise authorisation can be deleted. These deletes are refused with 400 and the code stock_committed.

Address an item by its id code

Item paths take the item's id, such as ITEM-0001. Do not use its uuid, or the integer id that Retrieve an item's sale settings and Retrieve an item's purchase settings return.

  • Every item write sits under item. The one exception is Upload an item's image, which sends image_base64 at the top level of a JSON body.
  • An item that an order uses cannot be deleted. Delete an item returns 409 for it, and retrying does not help.
  • Stock quantities are strings. In inventory adjustments, adjustment_amount and every quantity_* field arrive as text, so convert them before doing arithmetic.
  • A shipping rule names a zone by its dashed uuid. Take the 32 hex digits after zn_ in the zone's id and group them 8-4-4-4-12. In the same way, a shipping package's *_uom fields take a unit's bare uuid, not its prefixed id.
  • Return merchandise authorisation writes take the rma_ id; the reads under it take the code. The note and receipt reads return 404 for an rma_ id.
  • Lists come a page at a time. Records come under data. Send limit, then pass pagination.next_cursor as cursor until has_more is false.
