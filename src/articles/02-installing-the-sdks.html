The Python SDK installs from PyPI. The other six Exsited SDKs are installed from their source repositories rather than from a package registry such as npm or NuGet. This article explains what you need and how installation works. The developer documentation has the exact commands for each language.

See the installation guide

Before you start

For every SDK except Python you need read access to the SDK repositories on Bitbucket. If you do not have it, ask your Exsited contact.

Python

Run pip install "exsited>=4,<5". It needs Python 3.10 or newer, and the import is exsited.

The other six SDKs

1Clone the SDK's repository. Use the development branch; it is the main branch.

2Run one command in the clone to install its dependencies or build it, for example npm install for JavaScript. The table below lists the command for each language.

3Point your project at the clone. The installation guide shows the path to use for each language. Keep the clone next to your project, because those paths are relative.

What each SDK needs

Language You need Command
Python Python 3.10 or newer pip install "exsited>=4,<5"
JavaScript Node.js 18.17 or newer npm install
PHP PHP 8.2 or newer and Composer 2 composer install
Java JDK 21 and Maven 3.9 or newer mvn install -DskipTests
.NET .NET SDK 8.0.100 or newer dotnet pack src/Exsited.Sdk -c Release -o ./artifacts
Dart Dart 3.5 or newer (included with Flutter) dart pub get
Go Go 1.24 or newer go build ./...

Keeping the SDK up to date

For Python, run pip install -U "exsited>=4,<5". For the others, run git pull in the clone. PHP, Dart and Go read the clone directly, so they pick up the change straight away. JavaScript reads its built copy, so run npm install in the clone after you pull. Java and .NET use a built copy too, so run the command in the clone again. For .NET, if the version number did not change, also run dotnet nuget locals global-packages --clear before you restore your project.

Troubleshooting

The SDK files are missing after cloning

The clone is on the wrong branch. Clone again with --branch development; the repository's default branch does not hold the SDK.

Java cannot find the SDK

An error such as Could not find artifact com.exsited:exsited-sdk means the build step was skipped. Run mvn install -DskipTests in the clone, then build your project again. No extra repository or registry login is needed.

.NET cannot find the package

There is no public feed. Run dotnet pack src/Exsited.Sdk -c Release -o ./artifacts in the clone and add its artifacts folder as a package source, as the installation guide shows.
