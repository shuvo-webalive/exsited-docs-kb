The workflow, approval and alert APIs let your software manage how records move through your processes and who signs them off. You can create and change workflows and read their stages and milestones, list scheduled events and run or remove them, define custom events, approve or reject pending approvals and set up approval profiles and user groups. You can also read alerts, manage alert responsibilities, store action scripts, organise note groups and download note attachments. All seventy-one endpoints are available in all seven Exsited SDKs.

Good to know

Decisions and executed events take effect at once

Approving a pending approval runs the action it holds, and both approving and rejecting send notifications straight away. Execute an event runs its scheduled action now; use Remove an event if the action should not happen. An approval profile gates every matching transaction from the moment it exists, so create one only when those transactions should wait for approval.

A custom event adds messages to your communication profiles

Create a custom event adds a message for the event to every communication profile, and deleting the event leaves those messages behind. Its base_event takes an se_ id, not the evt_ id that List system events shows.

  • Change workflows under /workflows. Workflow settings are read only, and every write under /settings/workflows is refused with 400. A pre-built workflow cannot be deleted.
  • Records in use cannot be deleted. A custom event a workflow uses and an approval profile in use cannot be deleted.
  • Two paths serve the same alert responsibilities. /settings/alert_responsibilities and /alert_responsibility hold the same records. Writes from the settings path need the MANAGE_ALERT_RESPONSIBILITY permission.
  • Alerts for employees and labours are found by code. An account's alerts are found by the account's id.
  • Action script code is sent as a base64 file. Put a .js file in script_file, with its contents base64 encoded in content.
  • Lists come a page at a time. Records come under data. Pass pagination.next_cursor as cursor to read the next page, and stop when pagination.has_more is false.
