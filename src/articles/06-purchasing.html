The purchasing APIs let your software handle what you buy from your suppliers. You can create, change, cancel and read purchase orders, record supplier bills as purchase invoices, pay suppliers, and track the credit a supplier owes you through purchase credit notes and refunds. You can also generate ABA files from purchase payments, set up receive terms and work with returns of purchased stock to a supplier, though creating a return currently fails. All 89 endpoints are available in all seven Exsited SDKs.

Common tasks

You want to Use
Order goods from a supplier Create a purchase order with the supplier's account_id and its lines, inside purchase_order. Send "draft": true to save it as a draft
Add or change lines on a purchase order Change a purchase order's lines, giving each entry an op of add or change
Record the supplier's bill for a purchase order Create a purchase invoice from a purchase order with {"purchase_invoice": {}} as the body
Pay one purchase invoice Create a purchase payment for a purchase invoice, sending only payment_method_applications inside purchase_payment
Create a purchase order for a supplier in one call Create an express purchase order, with the supplier in account.id and the order in account.purchase_order
Record money a supplier pays back Create a purchase refund from a purchase credit note, with the reference of one of the supplier's payment methods as payment_method
Build an ABA file from purchase payments Generate an ABA file, listing each payment's id under aba_file.transactions

Good to know

Deletes cannot be undone, so cancel when you can

Deleting a purchase order, purchase invoice, purchase payment, purchase refund or purchase credit note, or one of their notes or files, cannot be undone. If you may need a purchase order or purchase invoice again, cancel it instead: Cancel a purchase order and Cancel a purchase invoice set the status to inactive, and the reactivate calls set it back to active. Delete a purchase order note file and Delete a purchase payment note file currently return 404 attachment not found, even for a file the note's file list shows. Create a return vendor authorization currently returns 500, so updating and deleting a return have not been confirmed to work. Only a draft return vendor authorization can be deleted; any other status returns 400 stock_committed.

Overpaying a supplier raises a purchase credit note

A purchase payment that pays more than its invoices take raises a purchase credit note. List a purchase payment's purchase credit notes shows it. Applying a purchase credit note to purchase invoices in turn records a purchase payment. Creating a purchase credit note cannot be reversed: it cannot be deleted without the permission to delete purchase credit notes, and the payment it draws on can no longer be deleted. Creating, applying and deleting a purchase credit note have not been confirmed to work yet.

  • Each record type has its own wrapper key. Write bodies go inside purchase_order, purchase_invoice, purchase_payment, purchase_refund, purchase_credit_note or return_vendor_authorization. The cancel and reactivate calls take an empty object.
  • Purchase order note calls take the purchase order's code, not its id. That covers listing, creating, reading and deleting notes and their files.
  • Some calls take only the prefixed id. The purchase credit note apply, note and delete calls take the pcn_ id, and deleting a return vendor authorization takes the rva_ id. The reads accept either the id or the code.
  • Amounts are decimal strings. Send purchase payment amounts as text, such as "1.00".
  • A purchase refund cannot be updated yet. Update a purchase refund currently returns 500, even for a valid body. It takes only alternate_date, reference, note and custom_attributes; any other key returns 400, and the amount cannot change.
  • Lists come a page at a time. Records come under data. While pagination.has_more is true, send pagination.next_cursor as cursor to get the next page.
